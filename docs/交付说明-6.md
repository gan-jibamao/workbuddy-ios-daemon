## 这一版改了什么

| # | 改动 | 解决的问题 |
|---|---|---|
| 0001 | 端口被占不再 `log.Fatal`，改退避重试（1s→2s→…→15s 封顶） | 两个实例抢 7863 时互相 `os.Exit(1)`，launchd 按 `ThrottleInterval=10` 重拉 → 端口反复易主 → 客户端 `ECONNREFUSED(-1004)` |
| 0002 | `GET /` → 302 `/panel/`（保留查询串） | 原来根路径 404。面板 HTML 用同目录相对路径（`theme.js` / `app.js`），直接挂根会 404，所以做跳转 |
| 0003 | 存活诊断：`[launchd]` 上次退出原因 / `[alive]` 每 30s 心跳 / `[signal]` 终止信号 | daemon 被外部杀掉时进程内什么都不留，只有这三行能把时间轴钉住 |

补丁在仓库 `patches/`，CI 里逐个 `patch -p1` 应用，并跑 3 个单测
（`TestListenWithRetryWaitsOnAddrInUse` / `TestListenWithRetryBindsAfterRelease` /
`TestPanelRootRedirect`）。

## 安装后怎么读日志

```
<JB>/var/mobile/Library/wb2api/server.log
```

启动第一屏会出现：

```
[launchd] state = running
[launchd] last exit reason = ...        ← 关键
[launchd] runs = N
[launchd] pid = NNNN
```

判据：

| 现象 | 结论 |
|---|---|
| `last exit reason = exited due to signal 9` | 被 SIGKILL —— 内存压力（jetsam）或外部 kill |
| `last exit reason = exited with code 1` | 走的是 `log.Fatal` 路径，往上翻那一行错误 |
| `last exit reason = exited with code 0` | 主动退出，找 `bye` 与 `[signal]` |
| 日志断在 `[alive]` 之后、且**没有** `[signal]` | 静默 SIGKILL，看那一行 `heap=` 数值 |
| 有 `[signal] 收到 terminated` 且随后 `bye` | 优雅关停（launchd bootout / 手动 kill） |

`[alive] uptime=25s heap=52MB sys=180MB goroutines=64` —— 被 SIGKILL 前最后一行
的 `heap` 就是内存侧的唯一线索。
