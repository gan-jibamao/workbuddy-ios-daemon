## 为什么怀疑「两个 job」

`-10` 日志里出现**相隔 1 秒的两次启动**：

```
15:52:07 BOOT 9721   15:54:06 BOOT 9738   15:58:07 BOOT 9878
15:52:08 BOOT 9723   15:54:08 BOOT 9742   15:58:08 BOOT 9879
                                           15:58:13 BOOT 9881
                                           15:58:16 BOOT 9882
```

plist 里 `ThrottleInterval=2` —— **同一个 job 不可能在 2 秒内被拉起两次**。
回看最早的日志（14:34–14:37），正是**两组序列交错、各约 20 秒周期**，
当时当成巧合，现在看是同一件事的早期形态。

而且 `-10` 的 `[boot]` 暴露了**两个不同的 jbroot 根**：

```
ppath = /var/containers/Bundle/Application/.jbroot-FE1B2F89EF123789/usr/local/bin/wb2api
cwd   = /private/var/mobile/Containers/Shared/AppGroup/.jbroot-FE1B2F89EF123789/var/mobile/Library/wb2api
```

同一个 `.jbroot-FE1B2F89EF123789`，父目录是两处。RootHide 的 jbroot 有两份镜像，
**同一份 plist 可能被两个域各加载一次**。

## 这一版加什么

### ① 自报身份

```
[boot] job label="..." xpc="..."
```

两个 job 会打出两个不同的值 —— 一眼分。

### ② `launchctl list` 原样倒出

```
[launchd] list: <每一行含 wb2api / workbuddy / gan. 的 job>
[launchd] list 共 N 行，匹配 M 行
```

另一个 job 的 label 就在这里，拿到就能 `launchctl bootout` 掉。

### ③ `launchctl print` 不再静默过滤

上一版过滤条件猜错（`last exit` / `state =` 一个都没命中），整条诊断
一个字都没输出。现在前 12 行原样落盘。

## 不需要装包也能先查的一件事（Filza，5 秒）

逐个打开看有几个 plist：

```
/private/var/mobile/Containers/Shared/AppGroup/.jbroot-FE1B2F89EF123789/Library/LaunchDaemons/
/var/containers/Bundle/Application/.jbroot-FE1B2F89EF123789/Library/LaunchDaemons/
```

**每个目录只应该有 `com.gan.wb2api.plist` 一个。** 多出任何一个（比如
`com.jkgl.workbuddy.plist`、旧版残留、或两份 `com.gan.wb2api.plist`）
就是双 job 的实证 —— 把它删掉即可。
