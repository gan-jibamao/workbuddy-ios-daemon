## 死因（两次，两种机制，都带真机证据）

### 第一次：per-process-limit（18 MB 天花板）—— -7 修掉

`JetsamEvent-2026-11-09-143726.ips`

```json
"name": "wb2api", "reason": "per-process-limit",
"rpages": 1152,            // 1152 × 16384B = 18.0 MB
"lifetimeMax": 1152, "states": ["daemon"]
```

只有它一个受害者 → 不是系统内存不足，是自身限额到顶。
`-7` 加 `JetsamProperties { JetsamMemoryLimit 256, JetsamPriority -49 }`。

### 第二次：pressured exit（空闲被回收）—— -8 修掉

`-7` 装上后仍出现三次死亡：

```
15:23:45 死 / 15:23:46 起   存活 3m25s
15:24:16 死 / 15:24:17 起   存活 30s    ← 其间零请求
15:24:27 死 / 15:24:28 起   存活 11s    ← 其间零请求
```

**CrashReporter 里一条新 JetsamEvent 都没有**，心跳显示空闲、`heap=2MB`。

`launchd.plist(5)`：`EnablePressuredExit` **默认 true** —— 任务空闲时可在系统
内存压力下被内核直接回收。这条路径不给信号、不写 panic、不产生 jetsam 记录，
日志里就只剩「上一条心跳之后忽然多了一次启动」。

Apple 自带的 `com.apple.syslogd.plist` 正是用 `<key>EnablePressuredExit</key><false/>`
保住常驻服务。

## 这一版的 plist

```xml
<key>EnablePressuredExit</key><false/>
<key>JetsamProperties</key>
<dict>
    <key>JetsamMemoryLimit</key><integer>256</integer>
    <key>JetsamPriority</key><integer>-49</integer>
</dict>
<key>ThrottleInterval</key><integer>2</integer>
```

`ThrottleInterval` 10 → 2：万一还是死，重启空窗从 10 秒压到 2 秒，
客户端撞上 `ECONNREFUSED` 的窗口缩小 5 倍。

CI 门禁：`EnablePressuredExit is False` + `JetsamMemoryLimit ≥ 128` +
`JetsamPriority ≤ -10`，少一条直接红。

二进制未改（13,483,088 B / platform=IOS / 签名 3267 页全过）。
