## 这一版改了什么

### ① 修掉 `ppath=?`（诊断恢复）

真机上 `os.Executable()` **直接返回 error**，于是 `logJobExitReason` 静默
return，`[launchd]` 那条「上次退出原因」一直是瞎的。

改成两条独立线索反推 jbroot：

1. **cwd** —— plist 的 `WorkingDirectory` 就在 `<jbroot>/var/mobile/Library/wb2api`，
   往上 4 层就是 `.jbroot-XXXX`
2. `argv[0]`（绝对路径时）
3. 都失败才回退 `/var/jb`

拿到 jbroot 后 exec 该目录下的 `launchctl`，把 launchd 记着的
`last exit reason` / `state` / `runs` / `pid` 抄进日志。

**装完这一版，日志里一定会多出：**

```
[launchd] last exit reason = ...
```

或（反推失败时）：

```
[launchd] 无法反推 jbroot，跳过上次退出原因
```

### ② GC 收紧

plist `EnvironmentVariables` 加：

```xml
<key>GOGC</key><string>25</string>
<key>GOMEMLIMIT</key><string>24MiB</string>
```

堆本身只有 2~3MB，但 Go 默认 `GOGC=100` —— 堆涨到上次存活量的两倍才回收，
请求一密集 RSS 就容易顶上去。`GOGC=25` 收紧节奏，`GOMEMLIMIT` 只是软上限
（超了只加频回收，不会 OOM）。

CI 门禁同步断言这两个键存在。

## 下一步判据

装完跑一段时间，把 `server.log` 发过来，只看一行：

```
rg '\[launchd\]' <log> | tail -3
```

| 输出 | 结论 |
|---|---|
| `last exit reason = exited due to signal 9` | 外部/内核 SIGKILL（沙盒或信号杀） |
| `last exit reason = exited with code 1` | 走的是 `log.Fatal` 路径 |
| `last exit reason = exited with code 0` | 主动退出 |
| `无法反推 jbroot` | 两条线索都断了，换 `sysctl` 或硬编码路径再试 |
