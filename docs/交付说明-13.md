## 根因：job 落在 user/501 域

`-12` 首次拿到 `launchctl print` 的真实输出：

```
Warning: Please switch to user/foreground/com.gan.wb2api service identifier
user/501/com.gan.wb2api = {
    active count = 1
    path = /private/var/containers/Bundle/Application/.jbroot-…/Library/LaunchDaemons/com.gan.wb2api.plist
    type = LaunchDaemon
    state = running
    program = /var/containers/Bundle/Application/.jbroot-…//usr/local/bin/wb2api
```

plus `launchctl list`：

```
10136  0  com.gan.wb2api
8183   0  UIKitApplication:com.tencent.workbuddy.app[7290][rb-legacy]   ← 官方 App，无关
```

plist 里 `UserName = mobile` → launchd 把这个 job 当**用户级 agent**，落在
`user/501` 域。**iOS 回收用户会话时，会把整条 user 域的 job 一起带走。**

这一条同时解释了全部历史现象：

| 现象 | 解释 |
|---|---|
| 不定时、间隔乱 | 取决于系统何时回收 mobile 会话 |
| 空闲也死 | 会话回收与请求无关 |
| 无 `JetsamEvent` | 不是内存杀，走的是会话回收路径 |
| 无 `bye` / 无 `[signal]` | 不是优雅退出，也不是 SIGTERM |
| 同一 pid 能活 40 分钟 | 那段时间没有回收事件 |

`-12` 实测：`pid=10136` 从 16:16:56 连续活到 16:59:41（40 分 30 秒），
`heap=1MB sys=18MB`。说明进程本身没有问题，问题在**它被放在哪个域**。

## 这一版改了什么

### ① `UserName: mobile` → `root`（`GroupName: wheel`）

不绑 mobile 会话 → job 落 `system` 域，与 Apple 自带守护进程同域。

### ② postinst 强制归位 + 自检

```sh
U=$(id -u mobile 2>/dev/null || echo 501)
for d in "user/$U" "gui/$U" system; do
    launchctl bootout "$d/com.gan.wb2api" 2>/dev/null || true
done
launchctl bootout system "$PLIST"
launchctl remove com.gan.wb2api
sleep 1
launchctl bootstrap system "$PLIST"
sleep 1
launchctl print system/com.gan.wb2api   # 进 system 域就打印 state，没进就把原文打到安装输出
```

安装时会直接打印一行 `已装入 system 域` 或整段失败原文。

### ③ `launchctl print` 输出上限 12 → 40 行

`last exit reason` 在更靠后的位置，上一版被截断了。

## 注意（数据目录所有权）

数据目录仍是 `mobile:mobile`，daemon 以 root 运行 —— root 写不受 DAC 限制，
读写都正常。新生成的文件会归 root。若将来要改回 mobile 运行，
需 `chown -R mobile:mobile` 一次。
