## 二、这一轮修的四类问题

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | -23 的 38px 控件实测仍是 28px | 面板 `.xs{height:28px}` 是类选择器，元素级规则全被压过 | 所有规则挂 `html.ios-m`，特异性反超 |
| 2 | 输入框设了 min-height 没用 | iOS 的 `<select>` 不认 `min-height` | 改写成确定 `height:38px`；复选框靠 label 撑到 44px |

| 4 | 卡片标题是空的 | 账号表第一列是装饰点 `.mark`，旧规则按 `td:first-child` 取标题 | JS 打 `data-role`（mark/title/field/acts），标题取第一个非装饰列 |

## 三、排版规格

- 4px 网格；字号三级：卡片标题 14.5/650，字段值 13/400，字段标签 11/500

- 配置页八个分区折叠，默认展开「服务」「分域配置」，选择存 `localStorage`
- 顶栏 48px，标题省略号；抽屉 292px / 80vw，条目 44px
- 输入 16px（Safari 不放大）；按钮 ≥38px，图标按钮 ≥38px
- 刘海与 Home 指示条安全区（`env(safe-area-inset-*)`）

## 四、审计口径与结果

脚本在每个视图里按表头灌对抗性数据（超长 UA、UUID、7 位数、空值、按钮），再逐元素检查：

1. 横向溢出（排除滚动容器内的元素）
2. 文本裁切（`scrollWidth > clientWidth` 且 `overflow != visible`）
3. 触摸目标 < 34px
4. 文字对比度 < 3.6（WCAG 近似）

结果（393×852，明/暗各一遍）：**溢出 0 / 裁切 0 / 小触摸目标 0 / 低对比 0**
（胶囊这类半透明底的 chip 会因 alpha 混合被误判，已单独排除）。
