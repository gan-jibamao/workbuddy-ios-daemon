## 死因定案（真机 jetsam 记录）

`/var/mobile/Library/Logs/CrashReporter/JetsamEvent-2026-11-09-143726.ips`

```json
"name"        : "wb2api",
"reason"      : "per-process-limit",
"rpages"      : 1152,          // 1152 × 16384B = 18.0 MB
"lifetimeMax" : 1152,
"priority"    : 40,
"states"      : ["daemon"],
"age"         : 463813948
```

- 整场事件**只有 wb2api 一个受害者** → 不是系统内存压力，是它自己的进程限额到头。
- `-6` 的心跳记过 `sys=17MB` → 空闲就贴着 18 MB 天花板。
- 一次对话请求把 RSS 顶过 18 MB → 内核 SIGKILL → 没有 panic / 没有 `bye` /
  没有 `[signal]`，launchd 按 `KeepAlive` 立刻重拉。
- 所以日志表现为「每个请求结束 0~2 秒后必重启」。

## 这一版改了什么

`packaging/com.gan.wb2api.plist` 加：

```xml
<key>JetsamProperties</key>
<dict>
    <key>JetsamMemoryLimit</key><integer>256</integer>
    <key>JetsamPriority</key><integer>-49</integer>
</dict>
```

`JetsamMemoryLimit` 单位 MB。对照 Apple 自带的 iOS `com.apple.timed`：
`JetsamMemoryLimit 2500 / JetsamPriority -49`；Dopamine 自用守护进程用 `128`。
**不写这两个键，launchd 就按 mobile 用户守护进程的默认值给 ~18MB。**

CI 增加 plist 门禁：少 `JetsamMemoryLimit ≥ 128` 或 `JetsamPriority ≤ -10` 直接红。

二进制与 -6 逐字节相同（13,483,088 B，platform=IOS，签名 3267 页全过），
只换了 plist。

## 装完怎么判「真的好了」

```sh
rg -c 'loaded [0-9]+ account' <JB>/var/mobile/Library/wb2api/server.log
```

这个计数**不应该再涨**。另外：

```
[alive] uptime=2m0s heap=... sys=... goroutines=...
[alive] uptime=2m30s ...
```

每 30 秒一行，连续出现 = 还活着。发一个对话请求之后**不应该**紧跟着出现
「loaded 2 account(s)」。
