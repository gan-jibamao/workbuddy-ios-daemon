## 加了个 prerm

**问题**：`apt remove` 只删包内文件，**进程不是 dpkg 管的东西**。没有 prerm 时：

- 二进制被删，但已在跑的进程带着被删的 inode 继续服务，直到重启；
- plist 被删，launchd 内存里那条 job 还在，`KeepAlive` 继续拉；
- 用户以为卸了，其实还在跑。

**prerm 做的事**（`packaging/prerm`，1,602 B）：

```sh
for d in "user/$U" "gui/$U" system; do
    launchctl bootout "$d/com.gan.wb2api"
done
launchctl remove com.gan.wb2api            # 兜底
# 等 3 秒优雅退出（daemon 有 SIGTERM 路径）
alive && killall -9 wb2api                 # 仍在才动硬的
```

- 三个域都试：RootHide 的 job 落在 `user/foreground`，不是 `system`；
- 判活用 `ps -A | grep '[w]b2api'`，不依赖 `pgrep`（不是每台都装）；
- 全程写 `$DATA/install.log`，卸载也能留痕。

## 数据目录照旧不动

`config.json` / `auths/` / `server.log` / `install.log` 从来不在包的文件清单里：

```
data.tar 只有三个文件
  var/jb/Library/LaunchDaemons/com.gan.wb2api.plist
  var/jb/usr/local/bin/wb2api
  var/jb/usr/local/bin/wb2api-doctor
```

重装后账号与配置照旧（实测：jbroot 从 `FE1B2F89…` 改名到 `6DA17554…` 那次，`auths/` 仍是 4 个账号）。

要彻底清干净才需要手动：

```sh
apt remove com.gan.wb2api
rm -rf /var/mobile/Containers/Shared/AppGroup/.jbroot-*/var/mobile/Library/wb2api
```

## CI

- `dash -n packaging/prerm` 语法门禁
- `cp packaging/prerm "$ROOT/DEBIAN/prerm"` + `chmod 755`
- 产物核对：`control.tar` 里应有 `control` / `postinst` / `prerm` 三个文件，prerm 权限 755

## 升级路径

`dpkg` 升级时会先跑旧包的 `prerm upgrade`，再跑新包的 `postinst`。所以从 -17 升 -18 时
会先停服务、再重装重起 —— 空窗 1~2 秒，比之前「postinst 里 bootout 再 bootstrap」更干净。
