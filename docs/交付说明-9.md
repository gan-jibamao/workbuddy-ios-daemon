## 为什么还要 -9

`-8`（`EnablePressuredExit=false`）之后出现新形态：

```
15:35:12 起 → #001…#009  连吃 9 个请求、撑 91 秒   ← 历史最好
15:37:10 死 → 15:37:11 / 15:37:19 / 15:37:21   连起三次，每次存活 2~8 秒
15:38:03 死 → 15:38:33 / 15:38:36 / 15:38:38   连起三次，每次存活 2~3 秒
```

- **无新 JetsamEvent** → 不是 per-process-limit
- **`EnablePressuredExit` 已 false** → 不是空闲回收
- **无 `bye`、无 `[signal]`** → 不是优雅退出、也不是收到信号

剩下最可能：`mobile` 用户守护进程的**沙盒 reject**（部分沙盒违规直接 SIGKILL，不留遗言）。

## 这一版改了什么

### ① 签名带 entitlements

`packaging/wb2api.entitlements`：

```xml
<key>platform-application</key><true/>
<key>com.apple.private.skip-library-validation</key><true/>
<key>com.apple.private.security.no-sandbox</key><true/>
```

CI 用 `ldid -Spackaging/wb2api.entitlements wb2api` 签名，并断言二进制里
必须能 grep 到 `platform-application`（少了直接红）。

iOS 把带 `platform-application` 的进程当**平台守护进程**：不进 mobile 沙盒、
给 platform 档的 jetsam band。预期同时解掉
`[launchd] fork/exec launchctl: operation not permitted` —— 那条诊断通了以后，
日志里就能直接看到 launchd 记着的上一次退出原因。

### ② 启动打 `[boot]`

```
[boot] pid=NNNN ppid=1 ppath=<jbroot>/usr/local/bin/wb2api cwd=<jbroot>/var/mobile/Library/wb2api
```

「连续重启」到底是几个不同 pid、每次被谁拉起、跑在哪个目录，一看就清楚。

### ③ 心跳 30s → 10s

死亡时刻定位精度从 ±30 秒提到 ±10 秒。

## 风险与回滚

- 若设备拒绝这个 entitlements 签名，**postinst 的预检会拦住**（`wb2api -h` 失败）：
  不会 bootstrap、不会无限重启，安装输出里会打出原始错误。
- 真出问题的回滚：重装 `-8` 即可（`-8` 是无 entitlements 的 ad-hoc 签名）：
  `com.gan.wb2api_2026.11.9-daemon-arm64e-8_iphoneos-arm64e.deb`
- 数据目录（config.json / auths / data）不受影响，两版共用。
