## 上一版推断作废

`-11` 的 `[boot]` 打印：

```
16:04:56 [boot] job label="" xpc="com.gan.wb2api"
16:09:31 [boot] job label="" xpc="com.gan.wb2api"
16:09:34 [boot] job label="" xpc="com.gan.wb2api"
```

**全部同一个 `XPC_SERVICE_NAME` → 只有一个 launchd job。**
「双 job 轮流跑」这条假设不成立，作废。

但同一次日志拿到更硬的事实：

```
16:04:56 BOOT 10002 → 之后 4 分 35 秒纯空闲（零请求、零错误、只有心跳）
16:09:30 静默死亡   → sys=13MB（GOGC=25 生效），离任何内存限额都很远
```

**空闲也会被杀**，且内存侧证据全部排除。

## 为什么 [launchd] 一个字都没输出

`jbrootGuess()` 只取**第一个**候选就 return。而真机有两条根：

```
exe: /var/containers/Bundle/Application/.jbroot-FE1B2F89EF123789/
cwd: /private/var/mobile/Containers/Shared/AppGroup/.jbroot-FE1B2F89EF123789/
```

`launchctl` 只在其中一条里；取到没那条 → 两个 `os.Stat` 都失败 → 循环走完 →
函数静默 return，一行日志都不留。

## 这一版

- `jbrootCandidates()` 列出**所有**根
- 每个根 × `usr/bin` / `bin` / `usr/local/bin` 三种位置找 `launchctl`
- 无论结果如何，必定留下可读的一行：

```
[launchd] jbroot 候选: <根1> , <根2>
[launchd] 使用 <launchctl 路径>
[launchd] list: <每一行含 wb2api 的 job>
[launchd] print: <前 12 行原样>
```
或
```
[launchd] 12 个候选路径里都没有 launchctl
```

- `ThrottleInterval` 2 → 1：死亡到重拉的空窗再压一半

## 已经排除的死因

| 假设 | 证据 |
|---|---|
| 端口被 App 内嵌服务抢 | App 已卸载；`address already in use` 12 条全在 14:36 之前 |
| 18MB per-process-limit | 加 JetsamMemoryLimit 后仍死；`JetsamEvent` 无新增 |
| 空闲被 pressured exit 回收 | 已 `EnablePressuredExit=false`，仍死 |
| 内存增长 | `heap=1~2MB`、`sys=13MB`，且纯空闲时死 |
| 双 launchd job | `XPC_SERVICE_NAME` 全部相同 |
