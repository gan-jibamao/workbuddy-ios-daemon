## 真凶：18MB per-process-limit

不是网络，不是 provider 配置，也不是用户会话回收。**是内核按内存限额杀掉进程。**

| 证据 | 出处 |
|---|---|
| `"reason":"per-process-limit","rpages":1152,"lifetimeMax":1152` | `JetsamEvent-2026-11-09-143726.ips`。1152 页 × 16KB = **18.0MB** |
| 每次死亡前 `sys` 从 13/17MB 爬到 **18~22MB**，然后断在心跳上 | 三份 server.log，每次死亡都是这个形状 |
| 每代 predecessor 的 launchctl 状态都是 **-9**，`[signal]` **0 行** | `launchctl list` / 全日志 grep |
| **开 4 个对话即复现**：17:12:44–49 四条流式 200 全成功，17:12:52 进程消失 | `shared-D391D008_server.log` |
| 17:14:24 心跳 `sys=21MB`，17:14:36 又被杀 | 同一份日志 |

## 为什么 -7 的 `JetsamProperties` 从来没生效

`launchctl print` 每代都写着：

```
user/501/com.gan.wb2api = { type = LaunchDaemon, state = running, domain = user/501 }
Warning: Please switch to user/foreground/com.gan.wb2api service identifier
```

job 落在 **user/501 域**。plist 的 `JetsamProperties` / `EnablePressuredExit`
是给 system 域 job 用的；在用户域里这些键是空转。`-13` 的
`launchctl bootstrap system` 没成功，回退的 `launchctl load -w` 又把它装回用户域 ——
所以上限一直是 mobile 守护进程默认的那 18MB。

## 这一版怎么修

进程**自己**把上限抬上去，不依赖 job 落在哪个域：

```go
// cmd/server/iosmem_darwin.go
//   XNU bsd/sys/syscall.h: __memorystatus_control = 440
//   memorystatus.h: MEMORYSTATUS_CMD_SET_JETSAM_TASK_LIMIT = 6，flags = 字节数
r, _, e := syscall.Syscall6(440, 6, uintptr(os.Getpid()), 256<<20, 0, 0, 0)
```

需要 `com.apple.private.memorystatus`（已打进签名，CI 校验存在）。

同时：

- `GOMEMLIMIT` 24MiB → **14MiB**。24MiB 是给错了的药：等于允许 Go 自己把进程喂到
  18MB 上限之上。`GOGC` 25 → 20，`GODEBUG=madvdontneed=1` 让归还的页真正还给内核。
- 心跳加 **`rss=`**（`getrusage().Maxrss`）—— 内核记账的是它，不是 Go 的 `sys`。
- `launchctl print` 上限 40 → **200 行**。40 行正好截在 `trampolined`，
  `last exit reason` 在后面。
- 启动时把 CrashReporter 里最近 3 个 `JetsamEvent-*.ips` 抄进 server.log。
- postinst 每步写 `$DATA/install.log`（`id -u`、bootstrap/print 原文、回退标记）。

## 装完先看这一行

```
[launchd] grep: 2026/11/09 xx:xx:xx [boot] uid=... euid=... jetsam=已抬到 256MB ret=0
```

- **`jetsam=已抬到 256MB ret=0`** → 成了。4 个并发对话不该再断。
- **`jetsam=抬高失败 ret=-1 errno=1`** → entitlement 没被认，走退路（14MiB 那条），
  把这一行发回来，下一版改成 system 域 bootstrap。

顺带会看到的心跳：

```
[alive] pid=... uptime=... heap=2MB sys=17MB rss=??MB goroutines=35
```

`rss` 就是内核账本上的数。它的峰值决定还会不会撞限额。

rg '\[alive\]' server.log | tail -3      # pid 不变、rss 稳定
